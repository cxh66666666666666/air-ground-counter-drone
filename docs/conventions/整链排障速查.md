# 整链排障速查（`backend:=full`）

> 面向"跑一批实验"的**可执行检查单**。故障判据与根因细节见 ADR，本文只给**判别顺序与处置**。
> 相关决策：[ADR-0005](../adr/0005-px4-link-uxrce-dds.md)（uXRCE 链路）、[ADR-0072](../adr/0072-px4-attitude-quaternion-field-order-and-full-chain-observation-fix.md)（姿态字段序）、[ADR-0075](../adr/0075-uxrce-entity-creation-intermittent-failure-and-infra-retry.md)（残留孤儿 / 运行前清场 / infra 重试）、[ADR-0076](../adr/0076-capture-scenario-tracking-milestone-not-terminal.md)（capture 终态语义）。

## 0. 三条环境铁律

| 项 | 值 / 做法 | 原因 |
|---|---|---|
| `ROS_DOMAIN_ID` | **保持默认 0** | 自设非 0 域（实测 77/81）→ lifecycle **服务数据面不通**（`ChangeState` 一律超时），话题却正常 |
| `ROS_AUTOMATIC_DISCOVERY_RANGE` | `LOCALHOST`（同机多进程验证足够） | 本机 `SUBNET` + WSL2 `eth3` 上行会**间歇性全失效**（`ros2 node list` 空） |
| 清理进程 | **禁止** `pkill -f "<名字>"` | 模式会匹配到该 shell 自身命令行 → 自杀（Exit -1）。用 PID：`kill $PID`，或 `pgrep -f "xxx[y]"` |

## 1. 启动前检查（每批必做，约 30 秒）

```bash
# ① 无本项目残留（含**桥节点与 tf**——它们不在 install/agc_* 下）
ps -eo pid,cmd | grep -E "[i]nstall/agc_|[M]icroXRCEAgent|[p]x4_sitl|gz sim|[p]arameter_bridge|[s]tatic_transform_publisher" | head

# ② 清 DDS 共享内存残留段（本机单 run 约余 100 段，累积数百段会致 SHM 端口初始化失败）
ls /dev/shm | grep -c fastrtps
rm -f /dev/shm/fastrtps_*          # 仅确认无 ROS 进程后执行

# ③ 环境
echo $ROS_DOMAIN_ID                # 应为空或 0
export ROS_AUTOMATIC_DISCOVERY_RANGE=LOCALHOST

# ④ 工具链二进制在位
ls -l toolchain/bin/MicroXRCEAgent toolchain/PX4-Autopilot/build/px4_sitl_default/bin/px4
```

> ① 中的**桥 / tf 节点**是最易漏的一类：本体在 `/opt/ros/jazzy/lib/...`，命令行**不含** `install/agc_`。
> 正常路径下 runner 的进程组回收会收干净；只有**外部终止**（断网 / 宿主只杀 leader）才会逃逸为孤儿。
> `episode_runner` 已在每次 episode 前自动做同口径清场（[ADR-0075](../adr/0075-uxrce-entity-creation-intermittent-failure-and-infra-retry.md)(g)），但**不**清 `/dev/shm`。

## 2. 故障判别表

| 症状（日志 / 结果） | 首判依据 | 处置 |
|---|---|---|
| `ERROR [uxrce_dds_client] create entities failed: participant: 255`，且**无** `created rt/fmu/out/* data writer` | agent 侧 `establish_session → create_participant` 耗时 **> 1 s**（PX4 硬编码预算） | 按[「启动前检查」](#preflight)清场 + 清 shm 后重跑；先查是否有残留桥 / tf 孤儿（最常见真因） |
| `air_odom=0` / `start rejected: air_hover_timeout` | 上一条的**下游后果**（own PX4 无 writer → 无 `/agc/air/odom`） | 同上；**不要**先怀疑 EKF / 起飞时序 |
| `/clock` 不推进 / `clock_not_progressing` | 无 `ros_gz_bridge` → 无 `/clock`；`use_sim_time` 节点时间冻结为 0 | 查桥进程是否在跑；查 gz 是否启动成功 |
| `Yaw estimate error` / 无法 arm | ①`PX4_SIM_MODEL` 未设 `gz_x500`（无磁罗盘）；②时间同步未禁（负时间戳） | 确认 launch 注入 `PX4_SIM_MODEL=gz_x500`、`UXRCE_DDS_SYNCT=0` |
| `cmd_vel_loopback_missing` | 地面命令链未活（唯一执行口无输出） | 查 `collision_monitor` / 命令源是否起来；属启动门，不属物理 |
| `odom_invalid` | `ground_odom_adapter` 晚到或地面 odom 失效 | 放宽启动门限（`--ready-timeout-s`）；查 `/agc/gt/agc_car` |
| `Publisher already registered for node name: 'xxx'` | 上一次 run 的**同名游离节点**仍在 DDS 图中 | 按[「启动前检查」](#preflight)清场（这类节点会污染本期证据） |
| `ros2 node/service list` 为空但节点确实在跑 | graph 查询**不可靠**（本机已知） | **不得**以 graph 作门禁；用**首个服务调用**探活（见下） |
| 首次服务调用超时、之后正常 | 发现预热 | 先发一次 `get_state`（忽略结果）再长超时重试 |
| `trajectory_tracker: 已获目标后参考 / 目标失效 → 显式 hold` | 契约 C10 的**自保语义**（非 bug） | 若是"固定航迹"臂，检查 `air_tracking_ref:=off` 是否生效 |
| `s08` 落 `TRACKING_SUCCESS` 而非 `INTERCEPT_CONFIRMED` | capture 场景需 `tracking_milestone_is_terminal: false` | 查场景覆盖（[ADR-0076](../adr/0076-capture-scenario-tracking-milestone-not-terminal.md)）；`t_max` 超时会落 `TIMEOUT` |

## 3. 最小探活（不启整链）

```bash
source /opt/ros/jazzy/setup.bash && source install/setup.bash
ros2 service call /agc/task/get_state std_srvs/srv/Trigger '{}'   # 首次可能超时（预热），重试即可
ros2 topic hz /agc/air/odom --window 20                            # 整链：应有稳定频率
ros2 topic echo /px4_N/fmu/out/vehicle_status --once               # 多实例：注意命名空间 px4_N
```

## 4. 一批跑完后的收尾

1. 核对 `metrics/arms.json` 的 `infra_retry_protocol`（`retried_runs` / `max_retries_used`）—— **infra 率必须随报告报出**，不得读作臂效应。
2. 核对 `metrics/perception_health.json`（`no_pose/rmax/fov` 占比）——`rmax` 属**环境边界**（量程 12 m < 站距上限 15 m，对两臂对称）；`no_pose` 偏高说明空中位姿断供，按第 2 节排查；`fov_*` 偏高查指向 / 姿态。
3. 确认 `ps` 无残留（同[「启动前检查」](#preflight) ①）；若有，说明该批次有被外部终止的 run，需登记。
4. 作废批次**必须在产物内显式标注**（`arms.md` 顶部 / `INCOMPLETE.md`），禁止让后来人误读。

## 5. 多 worker（W7-c）前的前置条件

当前 `sweep_stale_processes` **不区分 worker 归属**（按项目特征 SIGKILL）→ 同机并行时后启动者会杀掉先启动者的进程。
**在隔离手段落地前只允许单 worker 串行**（风险登记见 [ADR-0075](../adr/0075-uxrce-entity-creation-intermittent-failure-and-infra-retry.md)(i)）。
