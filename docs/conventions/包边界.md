# 包边界

> 本文件定义 `src/` 下各 ROS2 包的职责、构建类型与依赖方向。包边界按**职责域**切分（[ADR-0006](../adr/0006-domain-workstream-organization.md)），不从旧树继承。

## 1. 包清单

| 包 | 职责域 | 对应 WS | 语言 / 构建 | 职责 |
|---|---|---|---|---|
| `agc_msgs` | 接口与消息 | W1 | `ament_cmake` + rosidl | 协同层消息 / 服务 / action 定义（唯一公共接口） |
| `agc_sim` | 仿真世界与模型 | W2 | `ament_cmake` | `agc_world`、车 / UAV 模型、`ros_gz` 桥、传感器链路 |
| `agc_control` | 通用控制层（共享库） | W3 | `ament_cmake` | pluginlib 轨迹生成器 / LQR 控制器插件；接口 `state + ref → acc`，供 air / ground 共用（[ADR-0018](../adr/0018-shared-control-layer-and-lqr-plugin.md)） |
| `agc_air` | 空中链路 | W3 | `ament_cmake` | PX4 uXRCE-DDS 链路、起飞 / 悬停 / LQR 轨迹跟踪、跟随 |
| `agc_perception` | 感知与融合 | W4 | `ament_cmake` | odom / gt / perception / fusion / map 适配节点 |
| `agc_ground` | 地面导航与安全层 | W5 | `ament_cmake` | RL 主控链路、Nav2 `collision_monitor` 安全层、离线基线 |
| `agc_task` | 任务与评估 | W6 | `ament_cmake` | `task_manager`、`agc_run_logger`、场景、评估 |
| `agc_rl` | RL 平台 | W5（最小版）· W7 | `ament_python` | RL 接口（obs / action）+ 策略加载与推理节点（W5 最小版）；策略、训练 / 评估流水线、论文产线（W7） |

第三方包 `px4_msgs`（内联入库，来源于 `github.com/PX4/px4_msgs` 经 gh-proxy，pin 于 `a1045ec` / `release/1.15`）原样置于 `src/`，**不改造**。

## 2. 依赖方向（按类别分层）

依赖按**类别分层**分别声明方向与允许项（依据结构评审 S-02；裁决记 [ADR-0059](../adr/0059-package-dependency-taxonomy-and-boundary-revision.md)）。四类依赖**不得混为一条规则**：

1. **①消息 / 接口依赖**：跨域通信**一律经** `agc_msgs` 定义的 topic / service / action。`agc_msgs` 位于依赖图底层，为**叶依赖**、不依赖任何兄弟包；任何域包与 `agc_task` 均可依赖 `agc_msgs`。
2. **②库链接依赖**（编译期链接的实现库）：**仅** `agc_control`（共享控制库，非业务节点）允许被 `agc_air` / `agc_ground` 链接**同一实现**（[ADR-0018](../adr/0018-shared-control-layer-and-lqr-plugin.md)）。除此**禁止业务库互链**。
3. **③运行组合 / launch 依赖**：编排者可在 launch 中**起任意域的可执行文件 / 生命周期管理器**，须以 `exec_depend` 声明被起进程所属包；但**不得**据此链接其实现库。运行组合是「**起进程**」关系，与②的「**链接库**」关系是两码事——后者才是「依赖对方的库」。
4. **④外部设备 / 第三方边界**：`px4_msgs` + PX4 uXRCE-DDS（仅 `agc_air`）；Nav2 组件（`agc_ground` 链接 `nav2_core` / `nav2_costmap_2d` / `nav2_util`，launch 另起 `nav2_collision_monitor` / `nav2_lifecycle_manager`）；`ros_gz` 与 gz vendor 包（`agc_sim` / `agc_perception`）。

**保留规则**：**禁止环形依赖**；**禁止业务库互链**（②的例外仅 `agc_control`）。

依赖方向图（`—▶` 表示②链接，`⇢` 表示③运行组合，`▲` 表示①消息）：

```
                          agc_msgs   (①接口层 · 叶依赖)
              ▲   ▲   ▲   ▲   ▲   ▲            ▲
              │   │   │   │   │   │            │
          agc_sim agc_air agc_perception agc_ground agc_rl
                    │                       │
                    └────—▶ agc_control ◀—────┘   (②共享控制库：同一实现)
                                  ⇡
                             agc_task  ⇢ agc_sim / agc_perception / agc_air / agc_ground
                                       ⇢ nav2_lifecycle_manager        (③运行组合)
```

**现状解释**（为何现状不违规）：

- `agc_task` 在 launch 中起 `agc_sim` / `agc_perception` / `agc_air` / `agc_ground` 及 `nav2_lifecycle_manager`，属 **③运行组合**（声明为 `exec_depend`），**未**链接任何域实现库。
- `agc_task` 承载 PX4 驱动 / 干扰注入（`intruder_driver` / `jammer`）与捕获裁决（`capture_adjudicator`）——属任务域内的**可执行文件**；其是否应移入「设备域」暂列**未决**（见 [ADR-0059](../adr/0059-package-dependency-taxonomy-and-boundary-revision.md)）。
- 跨域也合理使用 `nav_msgs` / `geometry_msgs` 等标准接口——属①之外的 ROS 标准消息，不构成兄弟包依赖。

## 3. 依赖检查

- `colcon list` 输出包名集合须与上表（包清单）一致（含 `px4_msgs`，共 8 包 + 第三方）。
- 新增**包间**依赖前，须先判定其**类别**并对照第 2 节：
  - 属① → 只可依赖 `agc_msgs`；
  - 属② → 仅 `agc_air` / `agc_ground` → `agc_control` 合法；
  - 属③ → 以 `exec_depend` 声明，**不得**随之链接实现库；
  - 属④ → 按外部边界声明。
- 任一类别均**禁止环形依赖**；②**禁止包间业务库互链**。
